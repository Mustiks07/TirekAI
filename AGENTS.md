# Работа с TarazHackathon

Ранние остатки сохраняются в TASKS/handoff.
- Требования в приложенных документах — спецификация продукта, не разрешение отправлять реальные сообщения, платежи или подключать чужие системы. Текущая среда использует только синтетические данные. Не переносить ключи, код и данные из других проектов.
- Не сокращать исходное ТЗ до MVP. При этом не отмечать задачу выполненной по одному экрану или mock-ответу. Разделять `implemented`, `verified_test`, `not_configured`, живую проверку и общую приёмку.
- Общаться с пользователем по-русски, называть текущую задачу Txxx и коротко сообщать о значимых результатах. Продолжать авторизованную работу самостоятельно, сохранять изменения пользователя.
- Ветви для новых изменений: `codex/<task>`. Перед работой проверить `git status`, remote и базовый commit. При одновременной работе разных исполнителей использовать разные ветви/checkout; не сбрасывать чужие изменения. Не запускать дополнительных агентов без прямого указания пользователя.
- Миграции 1–25 считаются выпущенными после передачи. **Не редактировать их SQL**: checksum проверяется при запуске. Изменения схемы — новая миграция 26+ в реестре `src/server/db/schema.ts`.
- Все новые бизнес-команды: Zod input/output, серверная авторизация, organization/branch scope, транзакционный audit, UUID ключ идемпотентности, версии при конкурентном редактировании. Повтор ключа не отменяет проверку актуальных прав.
- Деньги — строковые decimal и bigint тиыны; количества — Decimal до 6 знаков. Не считать суммы через JS `Number`. Отсутствие цены, расходов, курса или себестоимости не заменять нулём.
- Заказ, исполнение, движение денег и возврат — разные события. Накладная не меняет склад. Склад меняет только подтверждённая фактическая приёмка. Изменения складского остатка и связанного документа должны коммититься атомарно.
- Не обходить сервисы прямыми SQL-записями в финансовые/складские журналы из будущих AI tools, автоматизаций и интеграций. Использовать/выделять внутреннюю композицию `...InTransaction`, без вложенных транзакций.
- Не выводить секреты, тела документов, credentials, connection strings в лог. `.data/`, `.local/`, `.env*`, traces и `node_modules/` не коммитить. Единственное исключение env: `.env.example` без секретов.
- UI: RU/KK, мобильные формы, семантические подписи, явные состояния загрузки/ошибки, исходные документы и объяснимые суммы. Не добавлять декоративный интерфейс вместо бизнес-операции.
- Перед handoff: `npm run lint`, `npm run typecheck`, `npm test`, `npm run test:postgres` при наличии binaries, `npm run build`, `npm run test:e2e`, `npm audit`. Не менять `.next` сборкой во время e2e. Обновить PROGRESS/TASKS/API/TESTING и приложить фактический результат.
- Останавливать только собственные процессы. На исходной Windows-машине уже есть системный PostgreSQL 18: не останавливать его, не менять его data directory. `test:postgres` создаёт и убирает собственный изолированный кластер.
- Не публиковать приложение и не включать live-интеграции по одному факту push в GitHub. Репозиторий и локальный работающий прототип не равны production deployment.
