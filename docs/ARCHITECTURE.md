# Архитектура

Модульный монолит: Next.js App Router + React + TypeScript. Строгое разделение:

- `src/components`: формы и представления, без SQL, паролей провайдеров или принятия решений о правах.
- `src/lib`: клиентский API и KK/RU словари.
- `src/domain`: схемы команд, типы и политика разрешений.
- `src/server/platform.ts`: транзакционные операции identity/organizations/memberships/audit.
- `src/server/http.ts`: версионированный HTTP, cookie, лимиты входа, origin и нормализованные ошибки.
- `src/server/db`: единый SQL-интерфейс, адаптеры PGlite и pg, миграции.

Каждый запрос получает серверную сессию. Каждый запрос к организации заново проверяет membership. Переданная клиентом роль не используется. Филиальные ограничения применяются к спискам филиалов, команды и событий. Даже прямой вызов API проходит те же проверки, что интерфейс.

Миграция 1 содержит identity/основание; миграция 2 — clients/import_batches/import_rows, outbox_events, jobs и worker_heartbeat. Импортный сервис отделён от `jobs/worker.ts`. Подтверждение и outbox записываются одной транзакцией; обработчик резервирует lease и фиксирует клиента, строку и прогресс задания атомарно. Аудит и outbox — разные таблицы. Объектное хранилище, AI и видео пока не созданы.

В локальном PGlite web-процесс владеет БД, а явный worker-процесс раз в секунду вызывает ограниченный loopback-мост `/api/internal/worker`. Мост доступен только в локальном режиме с временным случайным bearer-секретом supervisor; пользовательская сессия не даёт доступ. Один вызов обрабатывает до 25 строк. PostgreSQL-worker использует тот же класс напрямую, без HTTP. Jobs и строки сохраняются в БД, а не в памяти процесса.

Локальный PGlite сохраняет PostgreSQL-данные на диске в одном процессе. Миграции имеют номер и SHA-256. Правка применённой миграции отвергается. Локальный lock с PID препятствует открытию каталога несколькими процессами. Stale lock удаляется только после проверки, что PID завершён.

Для нескольких экземпляров приложения и workers необходим PostgreSQL. Миграции внешней БД запускаются отдельной командой, без автоматического исполнения в каждом web-процессе. Миграции пока нужно выполнять одним исполнителем. API использует PostgreSQL-транзакции, но проверка на внешнем движке ещё предстоит.

Интерфейс не запрашивает микрофон или камеру. Внешние вызовы отсутствуют. Шрифт Noto Sans Variable включён локально с кириллическими наборами; CDN не нужен. Для поздних модулей PWA и realtime будут отдельные изменения.
