# Проверки основания, клиентов, склада и PWA

Стенд: Windows, Node.js 22.20.0, npm 10.9.3, Edge. Дата: 14.10.2026. PGlite in-memory для integration; отдельный файловый PGlite для e2e. Это контролируемые синтетические данные.

## Сервер

`npm test`, `tests/foundation.test.ts`: 15 тестов.

- Повторное применение миграции и неизменность истории.
- Хеши паролей/сессий и проверка неверного пароля.
- Только свои организации; подмена organization_id и анонимный запрос.
- Создание организации, timezone/KZT/synthetic и аудит.
- Правильный email, одноразовое приглашение и права сотрудника.
- Изоляция филиалов для команды и аудита.
- Чужой branch_id не создаёт приглашение.
- Нельзя назначить owner через входные данные.
- Истечение, отзыв и перевыпуск приглашений.
- Два запроса принятия дают один результат.
- Исключение отзывает все сессии; owner защищён.
- Создатель приглашения потерял полномочия.
- Истекшая сессия и logout.
- Лимит неверных попыток входа.
- Rollback при ошибке транзакции.

PGlite сериализует обращения; его тест повторов не доказывает конкурентную корректность PostgreSQL. Дополнительные проверки на отдельном PostgreSQL 18.2 описаны ниже; многопроцессная нагрузка остаётся в T008/T049/T051.

`tests/imports.test.ts`: 19 дополнительных проверок. Точные десятичные суммы/дробные количества/округление/нулевая маржа; настоящий CSV с BOM, кавычками, разделителями и физическими строками; ошибки и лимиты; генерируемые контракты; preview без бизнес-записи; идемпотентные confirm/outbox/job; повтор и исправление файла; конфликты после предпросмотра; tenant/branch scope; пагинация/версии; порции 25; смена lease; rollback при исключении после INSERT; три попытки и явный retry; отзыв доступа до исполнения и повтор собственником.

`tests/restart.test.ts`: ещё 1 проверка с файловой БД. Три независимых Node-процесса: первый записал 25/31 клиента и завершился, второй открыл ту же БД и завершил 31/31, третий не создал дублей. Каталог `.data/restart-*` игнорируется Git. Это проверка персистентности между процессами, не аварийный kill в середине commit. Mid-chunk сбой проверен инъекцией исключения с настоящим rollback в integration.

## Браузер

`npm run test:e2e`: 2 foundation-сценария и 1 сценарий `tests/e2e/imports.spec.ts`. Производственная сборка и worker запускаются автоматически на `127.0.0.1:3100`. На каждый запуск выделен новый каталог `.data/e2e-*`. Тестовый сервер/worker останавливает Playwright.

Проверяются регистрация, создание организации и филиала, приглашение, вход второго пользователя, принятие, ограничения UI/API, чужая организация, враждебный Origin, HttpOnly cookie, исключение и отзыв сессии, KK/RU, повторное открытие, ширины 360/390/430 px, ошибки браузера и axe WCAG A/AA. Снимки: `docs/evidence/desktop-ru.png`, `desktop-kk.png`, `mobile-kk.png`.

Обнаруженные и исправленные при QA проблемы: подсказка пароля/опции select входили в доступное имя; недостаточный контраст вторичного текста; открытие invite во фрагменте URL уже загруженной вкладки не обрабатывалось до добавления hashchange. Непройденный запуск не считается успешным результатом. Добавлены четыре unit-проверки KK/RU дат и смены календарного дня в часовом поясе организации.

Новый browser-сценарий: загрузка реального CSV, ошибки и дубль до записи, импорт двух корректных строк через worker, повтор файла, правка контакта, KK/RU, 360/390/430 px, axe и отказ технического bridge без секрета/с неверным секретом. Снимки `import-desktop-ru.png`, `import-mobile-kk.png` просмотрены. Исправлено сжатие карточек клиентов на мобильном экране; широкая таблица прокручивается внутри своего региона с клавиатурным фокусом. Первый запуск упал из-за недопустимого Unicode HTTP-заголовка в самом тесте; исправлено, финальный прогон целиком успешен.

## Склад и PWA

`tests/inventory.test.ts`: 15 тестов. Точные преобразования и запрет потери точности, распределение стоимости с остатком округления, генерация контрактов, SKU/версии/поиск, скрытие себестоимости от sales, изоляция складов/организаций, запрет изменения общего каталога филиальной ролью. Приёмка в bag/kg, средняя стоимость выдачи, сумма движений=баланс, повтор ключа/конфликт данных, rollback недопустимой операции, запрет складского остатка услуги. Две конкурирующие Promise-команды резервирования последней единицы дают один успех в сериализованном PGlite; это не доказательство многопроцессного PG. Проверены путь/приёмка без двойного остатка, исходная стоимость частичных возвратов после новой поставки, версия инвентаризации/недостача/излишек/резервы, неизменность единиц после использования и архив.

`tests/e2e/inventory.spec.ts`: формы каталога/единиц и склада → приёмка 2 bag по 2 kg → резерв → выдача резерва → возврат → путь/приёмка второго склада; API остатка/стоимости сверяется по ходу. KK/RU, axe, widths 360/390/430 и screenshots `inventory-desktop-ru.png` / `inventory-mobile-kk.png`. Исправлены неоднозначные accessible labels select и локализация сообщения об успешной операции. Первые неуспешные прогоны сохранены только в игнорируемых traces; финальный результат фиксируется ниже.

`tests/e2e/pwa.spec.ts`: валидный browser manifest через CDP, активный service worker, cache allowlist ровно offline HTML + 3 иконки после session API; offline API-запрос отклоняется, navigation показывает RU/KK fallback, возврат онлайн восстанавливает страницу. axe на offline-экране: 0 нарушений. `offline-kk.png` просмотрен. Нативная установка в OS и обновление уже установленного приложения этим тестом не доказываются.

## PostgreSQL 18.2

`npm run test:postgres`, `tests/postgres.integration.ts`: 7 / 7, 3.12 секунды непосредственно Vitest, без времени initdb. Временный сервер на случайном loopback-порту, SCRAM, синтетические данные, два независимых SQL-пула в одном тестовом OS-процессе. Проверены миграции 1–3 и их повтор; конкурентный резерв последней единицы (один успех); одинаковый ключ прихода (одно движение); устаревшая версия инвентаризации; параллельные outbox/worker для двух batches по 31 строке без дублей; смена lease и отказ старому обработчику; принудительное завершение backend с незавершённой записью, rollback и успешная следующая операция.

Первые попытки запуска runner выявили отказ прямого postgres с административным токеном Windows и удержание pipe после pg_ctl. Исправлены запуск через pg_ctl с ограниченным токеном и ожидание завершения launcher без наследуемых stdout/stderr pipes. Итоговый запуск целиком успешен, тестовый сервер автоматически остановлен. Системная служба PostgreSQL не изменялась.

Это подтверждает работу pg driver и конкурирующих SQL-соединений, но не нагрузку нескольких процессов приложения, kill сервера во время commit или восстановление из backup.

## Не проверено

Несколько OS-процессов workers/приложения с PostgreSQL под нагрузкой, аварийный kill приложения/сервера внутри commit, внешние провайдеры, restore из резервной копии, нагрузка 20 пользователей, p95, realtime, нативная PWA-установка/обновление Android/iOS, финансовые операции/заказы, партийный склад, XLSX/прочие импортные сущности, AI eval, video eval и отрасли. Автоматическая accessibility-проверка не заменяет проверку экранным диктором и полный аудит всех будущих модулей.

## Команды

`npm run lint`, `npm run typecheck`, `npm test`, `npm run test:postgres`, `npm run build`, `npm run test:e2e`, `npm audit`. PostgreSQL-набор запускается отдельно при установленных бинарниках; в CI пока не включён.

CI повторяет основные команды и устанавливает Chromium. Workflow ещё не запускался удалённо. Browser traces с данными тестовых форм сохраняются только в игнорируемых `test-results` / `playwright-report`.
