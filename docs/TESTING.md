## PostgreSQL 18.2

`npm run test:postgres`, `tests/postgres.integration.ts`: 11 / 11, 5.52 секунды непосредственно Vitest, без времени initdb. Временный сервер на случайном loopback-порту, SCRAM, синтетические данные, два независимых SQL-пула в одном тестовом OS-процессе. Проверены миграции 1–4 и их повтор; конкурентный резерв последней единицы (один успех); одинаковый ключ прихода (одно движение); устаревшая версия инвентаризации; параллельные outbox/worker для двух batches по 31 строке без дублей; смена lease и отказ старому обработчику; принудительное завершение backend с незавершённой записью, rollback и успешная следующая операция.

Первые попытки запуска runner выявили отказ прямого postgres с административным токеном Windows и удержание pipe после pg_ctl. Исправлены запуск через pg_ctl с ограниченным токеном и ожидание завершения launcher без наследуемых stdout/stderr pipes. Итоговый запуск целиком успешен, тестовый сервер автоматически остановлен. Системная служба PostgreSQL не изменялась.

Это подтверждает работу pg driver и конкурирующих SQL-соединений, но не нагрузку нескольких процессов приложения, kill сервера во время commit или восстановление из backup.
