# Демо TirekAI на 3–5 минут

Три сценария на заполненном тестовом магазине **Tirek Market** (синтетические данные; не реальное предприятие). Сценарии используют обычные экраны и сервисы приложения: ни история, ни ответ модели, ни экономический эффект заранее не записываются. Полное ТЗ этим демо не сокращается — это показ трёх сквозных процессов из готового объёма.

Проверено 16.10.2026 в облачном Linux-контейнере (4 vCPU, без GPU, Chromium): сценарии 1 и 2 пройдены в браузере полностью; сценарий 3 — только до статуса «модель не подключена», потому что ключей бесплатных моделей в облаке нет. Фактический протокол — [demo/rehearsal/rehearsal.json](demo/rehearsal/rehearsal.json), снимки экранов — `docs/demo/rehearsal/*.png`.

## Подготовка (один раз на машине)

PowerShell (Windows) или bash, в корне репозитория, сервер остановлен:

```powershell
npm ci
npm run db:seed:business   # Tirek Market: 3 филиала, 36 товаров, 72 заказа, 12 закупок…
npm run demo:prepare       # данные сценариев + сохранение исходного состояния демо
npm run build
```

`demo:prepare` через бизнес-сервисы:

- приглашает второго сотрудника «Данияр · согласующий (демо)» (роль manager, филиал 01) — второй человек для согласования; его вход и пароль только в игнорируемом `.local/tirekai-demo.json`;
- создаёт у «Тараз Снаб» предложение на зелёный чай и закупочный заказ: чёрный чай 40 × 1 250 ₸, зелёный чай 24 × 900 ₸, доставка 2 500 ₸; заказ проходит «на согласование → одобрено → отправлено вручную»;
- оформляет обычную продажу последних 8 пачек бумаги A4 со склада «Центральный» (заказ, выдача, оплата в кассу) — склад действительно пустеет, ситуация «Риск нехватки» становится критичной;
- добавляет ещё три предложения на бумагу A4: «Тараз Снаб» (коробка 5 пачек, минимум 2 коробки, доставка 4 000 ₸, 5 дней), «Береке Опт» (коробка 10 пачек, доставка включена, 2 дня), «Alatau Foods» (1 290 ₸ за пачку, **доставка не указана**);
- пересчитывает ситуации и копирует локальную базу в `.data/local-demo-baseline`.

Входы владельца — `.local/tirekai-business.json`, согласующего — `.local/tirekai-demo.json`. Эти файлы не коммитятся. Синтетическая накладная `docs/demo/invoice-ts-1042.jpg` (вымышленный поставщик, надпись «синтетический документ») создаётся `npm run demo:invoice`.

Для сценария 3 на машине показа в `.env.local` (не в Git): `ASSISTANT_PROVIDER=free`, `ASSISTANT_SYNTHETIC_DATA=1`, `GEMINI_API_KEY`, `OPENROUTER_API_KEY` — см. [AI_PROVIDERS.md](AI_PROVIDERS.md). Платные модели не используются.

## Перед каждым показом

```powershell
npm run demo:reset    # сервер должен быть остановлен (Ctrl+C)
npm run preview       # http://127.0.0.1:3000
```

Владелец входит в одном окне, согласующий — во втором (окно инкогнито или другой браузер). Язык интерфейса переключается кнопками ҚАЗ/РУС.

Автоматическая проверка того же пути: при запущенном `preview` — `npm run demo:rehearse` (кликает по экранам, пишет время шагов и снимки в `docs/demo/rehearsal`). После неё снова `demo:reset`.

## Сценарий 1. Накладная → OCR → проверка → фактическая приёмка (≈ 1,5 мин)

1. **Закупки** → заказ «Тараз Снаб · Отправлено вручную» (Демо: чай к накладной ТС-1042).
2. В блоке документа выбрать `docs/demo/invoice-ts-1042.jpg` → **Загрузить и распознать**. Распознавание локальное (Tesseract в отдельном процессе, без внешних сервисов), на стенде ≈ 3,6–4,2 с. Показать «Распознанный текст» и «Предполагаемые строки».
3. Форма проверки уже заполнена из распознавания: № ТС-1042, дата, 40 × 1 300,00, 24 × 900,00, доставка 2 500,00, итог 76 100,00. Подчеркнуть: это подсказки в редактируемых полях; строка без уверенного совпадения остаётся пустой, а не нулём.
4. Выбрать «Подтвердить документ и создать долг поставщику», основание → **Сохранить**. Система отказывает: «Есть расхождения с заказом» — поставщик выставил 1 300 ₸ вместо 1 250 ₸. Отметить «Проверены расхождения…», основание «Новая цена согласована» → сохранить.
5. **Подтвердить фактическую приёмку**: чёрный чай 40, зелёный 22 (две пачки не привезли), основание → подтвердить. Заказ — «Частично принято».
6. Итог: склад меняет только фактическая приёмка. На прогоне остаток «Центрального склада»: чёрный чай 583 → 623, зелёный 594 → 616. Загрузка и проверка накладной остаток не меняли; долг поставщику создан по подтверждённому документу.

## Сценарий 2. Нехватка → сравнение → черновик → согласование (≈ 1,5 мин)

1. **Сегодня** → «Критично: Риск нехватки товара: TM-034 · Бумага A4 · Центральный склад» → «Расчёт и действия». Видно: на складе 0, минимум 20 + страховой запас 5, не хватает 25, **на других складах 16** (альтернатива — перемещение), предложенный поставщик «Тараз Снаб», 38 500 ₸ с доставкой, формула и источники.
2. **Закупки → Поставщики и прайсы → Сравнить предложения**: товар TM-034, 25 единиц → **Рассчитать полную стоимость**. На прогоне:

   | Поставщик | Что покупаем | Полная стоимость | За пачку |
   | --- | --- | --- | --- |
   | Тараз Снаб | 5 коробок × 5 = 25 | 38 500 ₸ (с доставкой 4 000) | 1 540 ₸ |
   | Office Supply | 25 × 1 | 38 750 ₸ | 1 550 ₸ |
   | Береке Опт | 3 коробки × 10 = 30 | 40 500 ₸ (доставка включена) | 1 350 ₸ |
   | Alatau Foods | 25 × 1 | **не сравнивается: неизвестна доставка** | — |

   Что сказать: самая низкая цена за пачку у Alatau, но без условия доставки система не ставит её первой и не считает доставку нулём. «Береке» дешевле за пачку, но требует купить 30. Выбор по полной стоимости нужного количества — «Тараз Снаб»; решение остаётся за человеком.
3. **Сегодня** → та же ситуация → **Подготовить закупку** → «Черновик закупки создан».
4. **Согласования** → «Черновики» → открыть: TM-034 · Бумага A4 · Тараз Снаб · упаковка 5 × 6900 KZT · количество 25, бюджет 38 500 → **Отправить на согласование**. Владелец не может согласовать своё предложение.
5. Окно согласующего: **Согласования** → предложение → «Согласовать», основание → **Записать решение** (решение привязано к версии параметров).
6. Окно владельца: «Согласованы, не выполнены» → **Выполнить согласованное** — создаётся закупочный заказ «Тараз Снаб», 38 500 ₸, состояние «одобрено». Права проверяются повторно при исполнении. Деньги и склад не меняются до оплаты и фактической приёмки.

## Сценарий 3. Помощник на казахском и русском (≈ 1–1,5 мин)

Требует подключённой бесплатной модели (см. «Подготовка»). На стенде исполнителя модель не подключена — этот сценарий в облаке **не проходился**; экран показывает «Помощник пока не подключён».

1. **Помощник** → «Язык ответа: Қазақша» → «Шоттарда қанша ақша бар және клиенттер бізге қанша қарыз? Дереккөздерді көрсет.»
2. «Язык ответа: Русский» → «Что срочно закончилось на складе и сколько мы должны поставщикам?»
3. «Подготовь черновик закупки для ситуации с этикетками TM-036. Ничего не отправляй и не согласовывай.» — инструмент `draft_purchase_for_situation` создаёт только черновик предложения; согласование и исполнение — как в сценарии 2.

Как проверять ответ: суммы должны совпасть с карточками «Сегодня» и `npm run demo:rehearse` («Ожидаемые суммы из расчётного слоя»). На прогоне после сценариев 1–2: на счетах 6 382 778,75 ₸, должны клиенты 250 205,50 ₸, должны поставщикам 931 100,00 ₸. Под ответом — «Использовано: …» (вызванные инструменты) и «Источники». Числа, которых нет в данных инструментов, помечаются «проверьте их». Если модель ответила неверно или недоступна — это показывается как есть; запасного «правильного» ответа нет.

Голосовой ввод: кнопка «Записать вопрос» → расшифровка попадает в поле вопроса, её можно исправить до отправки (см. T056 в TASKS: локальное распознавание речи и его ограничения).

## Что не утверждать на показе

- Это синтетический магазин; цифры не являются результатом реального бизнеса и не доказывают экономический эффект. Пилот и сравнение «до/после» — T058.
- OCR проверен на синтетическом скане хорошего качества; на реальных фото качество нужно измерять (`npm run ocr:check`, T056).
- Внешние системы, платежи и сообщения в демо не подключаются.

## Восстановление исходного состояния

`npm run demo:reset` (сервер остановлен) возвращает базу к моменту окончания `demo:prepare`: удаляет загруженные документы, приёмки, предложения, согласования и разговоры показа. Если `.data/local-demo-baseline` отсутствует — выполнить заново `npm run demo:prepare`. Полностью с нуля: остановить сервер, удалить `.data/local`, `.data/local-demo-baseline` и `.local/tirekai-*.json`, затем `db:seed:business` и `demo:prepare`.
