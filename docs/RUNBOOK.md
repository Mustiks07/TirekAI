# Запуск и остановка

## Локальный процесс

Команда `npm run dev` или, после `npm run build`, `npm run preview` запускает web на `http://127.0.0.1:3000` и один worker импорта. Данные находятся в `.data/local`. PGlite живёт внутри web-процесса. Worker раз в секунду вызывает защищённый loopback-мост, который обрабатывает до 25 строк за вызов. Это не отдельная служба БД. Камеры и AI не запускаются. Worker печатает назначение/PID; секрет генерируется supervisor только в памяти.

Остановка web и worker: Ctrl+C в терминале запуска. Завершение любого дочернего процесса останавливает второй. Не завершать все процессы Node на компьютере и не удалять базу ради остановки. Если терминал потерян, найти PID конкретного порта через `Get-NetTCPConnection -LocalPort 3000 -State Listen`, проверить командную строку и путь процесса, затем остановить только процессы этого запуска (включая worker из лога).

Проверка ожидания очереди: задать `$env:WORKER_DISABLED='1'` перед локальным запуском; подтвердить импорт, остановить сервер, удалить эту переменную и запустить снова. Очередь продолжится. После аварии lease живёт до 30 секунд. `failed`/`cancelled` требуют кнопки повтора сотрудником с правами. Успешные порции повторно не записываются. Heartbeat старше 10 секунд показывает отсутствие обработчика.

Для выделенного PostgreSQL сначала `npm run db:migrate` одним исполнителем, затем web и отдельный `npm run worker` с DATABASE_URL. Worker не запускает миграции. Конкурентная обработка проверена с двумя worker-объектами через независимые PostgreSQL-пулы; отдельные OS-workers под нагрузкой ещё не проверены. Потребление при локальном простое: один Node-worker с опросом раз в секунду и PGlite внутри web; измерения CPU/RAM/p95 под нагрузкой ещё не выполнены.

Проверки Playwright временно занимают порт 3100 и отдельный `.data/e2e-*`. Они не используют `.data/local`. Нельзя одновременно открывать одну файловую базу в web и seed. Local lock показывает занятый PID; после аварии мёртвый PID очищается при следующем открытии. Если PID занят другим процессом, сначала проверить принадлежность, не удалять lock вслепую.

## Изолированные проверки PostgreSQL

`npm run test:postgres` требует установленного PostgreSQL. По умолчанию бинарники ищутся в `C:/Program Files/PostgreSQL/18/bin` (Windows) или `/usr/lib/postgresql/18/bin` (Linux); `PG_BIN` переопределяет каталог. На этом стенде проверен Windows/PostgreSQL 18.2; Linux-запуск отдельно не проверен, его следует выполнять обычным пользователем.

Runner создаёт `.data/postgres-tests-*`, случайный пароль SCRAM и свободный порт только на 127.0.0.1. Существующие базы, службы и DATABASE_URL не используются. Пароль передаётся initdb через временный файл в `.local`, удаляемый сразу после инициализации; затем только через окружение тестового процесса. Не публиковать дампы окружения. Логи сервера и синтетическая база сохраняются в игнорируемом каталоге.

На время команды работают отдельный сервер PostgreSQL (до 30 соединений), два SQL-пула до 10 соединений и Vitest. После успеха, ошибки теста или обычного Ctrl+C runner вызывает pg_ctl fast stop именно для своего каталога. При принудительном завершении самого runner автоматическая остановка не гарантируется: проверить путь `-D` процесса и выполнить `pg_ctl -D <точный каталог .data/postgres-tests-...> -m fast -w stop`. Не останавливать системную службу и не удалять PID-файлы работающего сервера. pg_ctl запускается со скрытым окном; в Windows использует ограниченный токен.

## Заказы и финансы

Миграция 4 применяется при следующем локальном старте; для PostgreSQL — штатной db:migrate перед приложением. Начальные данные прежних миграций не переписываются. Новые функции не запускают дополнительных workers, служб, банковских подключений или плановых платежей. Браузер обновляет списки после действий и по кнопке; realtime пока отсутствует.

При VERSION_CONFLICT обновить карточку и сверить последнее действие. При сетевой ошибке проверить журнал/заказ перед новым вводом: открытая форма сохраняет ключ повтора для неизменённого запроса, но после перезагрузки браузера ключ не восстанавливается. Возврат товара делается в заказе, возврат денег — отдельно в финансах. Нельзя менять SQL-журнал для исправления цифр. Сторно прочих ручных расходов ещё не реализовано.

## Ошибки

- `INTERNAL_ERROR` с requestId: проверить окружение, занятый каталог и версии миграций. Приложение не печатает в лог SQL, тела запросов или секреты.
- `UNAUTHENTICATED`: истёкшая/отозванная сессия, войти снова.
- `FORBIDDEN`: проверить организацию, роль и филиал; клиентский organization_id не предоставляет доступ.
- `INVALID_INVITATION`: проверить email, срок, отзыв/перевыпуск. Попросить собственника создать новую ссылку.
- `RATE_LIMIT`: ждать завершения 15-минутного окна. Не удалять ограничения для обхода поставщика.
- `Migration was modified`: вернуть прежний применённый SQL и добавить новую миграцию, не менять checksum вручную.

## Данные и резервные копии

Для локального синтетического стенда после остановки всех процессов можно сделать копию `.data/local`. Это ещё не принятый процесс восстановления AC17. Для живого PostgreSQL требуется отдельная процедура бэкапа, restore drill и роли БД (T053). Никаких автоматических разрушительных откатов или сбросов данных нет.

Секреты fixtures в `.local/fixture-accounts.json`. Не включать их в отчёты и снимки. `.env.example` содержит только пустые значения и безопасные локальные параметры.

## PWA

Service worker работает в браузере только после production preview, без отдельного OS-процесса. В dev новый worker не регистрируется. Для проверки чистого dev после preview при необходимости удалить регистрацию текущего localhost-origin через DevTools → Application → Service Workers; это не удаляет серверную PGlite БД. Cache Storage `basqaru-public-v1` содержит только публичные иконки/offline HTML. Не очищать все данные других origin.

После обновления закрыть/сохранить формы и использовать кнопку обновления приложения. Нативная установка выполняется только штатным браузерным подтверждением. Офлайн-баннер предупреждает, что перед повтором команды надо проверить результат после подключения; автоматического replay нет.

## T020–T030: worker, ключи и проверки

Worker (локально через `/api/internal/worker`, для PostgreSQL — `npm run worker`) на каждом тике: импорт, периодические задачи, эскалация, истечение предложений, обнаружение ситуаций (не чаще раза в 5 минут на организацию), автоматизации (outbox → исполнения), синхронизация МойСклад (не чаще раза в 15 минут) и входящие вебхуки. Повтор тика и перезапуск не дублируют результат. Ручной разбор автоматизаций — раздел «Автоматизации», журнал; повтор — кнопка «Повторить».

Переменные (только сервер, не в git): `ANTHROPIC_API_KEY`, `ASSISTANT_MODEL`, `INTEGRATION_ENCRYPTION_KEY` (32 байта base64; смена ключа делает сохранённые токены нечитаемыми — после смены токен вводится заново). Без них функции честно показывают not_configured, остальное приложение работает. Живой eval помощника: `npm run eval:assistant` с ключом в `.env.local` или окружении (расходует токены; запускать только с разрешения владельца бюджета), отчёт в `docs/evidence/assistant-eval-YYYY-MM-DD.json`.

### Подключение ключа AI (T026) — делает владелец

1. Создать файл `.env.local` в корне checkout (он в `.gitignore`, в git не попадает):
   ```
   ANTHROPIC_API_KEY=<ключ>
   ASSISTANT_MODEL=claude-opus-5-5
   ```
   В PowerShell без файла: `$env:ANTHROPIC_API_KEY="<ключ>"; npm run dev`.
2. Перезапустить `npm run dev` (или `npm run preview`). Next.js читает `.env.local` при старте; `npm run worker` и `npm run eval:assistant` читают его через `--env-file-if-exists`.
3. Проверить в приложении: «Помощник» → статус провайдера «настроено»; «Сегодня» → источник «AI-помощник». Первый вопрос: «Что требует внимания сегодня?» — в ответе должны быть источники; числа без источника помечаются.
4. Черновик правила (T025): «Автоматизации» → «Описать правило словами» → «Предложить черновик». Черновик не сохраняется сам.
5. Живой eval (расходует токены, 32 вопроса RU/KK на синтетических данных): `npm run eval:assistant`. Отчёт — `docs/evidence/assistant-eval-YYYY-MM-DD.json`; его можно приложить к приёмке T026/T027. Без ключа скрипт пишет not_configured и завершается с кодом 2.
6. Лимиты: владелец задаёт месячный бюджет токенов и максимум ответа в «Помощник» → настройки; при исчерпании ответ — budget_exceeded, без вызова модели.
7. Ключ не вставлять в чат, issue, коммит или лог. При утечке — отозвать в консоли Anthropic и заменить в `.env.local`.

Вебхук МойСклад: адрес `https://<APP_ORIGIN>/api/integrations/moysklad/<connectionId>/<token>` показывается один раз при сохранении токена. Нужен публичный HTTPS; локальный стенд его не получает.

Linux-контейнер: `npm run test:postgres` с `PG_BIN=/usr/lib/postgresql/16/bin` от непривилегированного пользователя (каталоги `.data`, `.local`, `node_modules/.vite*` должны быть доступны ему на запись); e2e с `PLAYWRIGHT_CHROMIUM_EXECUTABLE=/opt/pw-browsers/chromium`. После проверок 14.10.2026 серверы 3100 и временный кластер остановлены.

## T031–T040: подключения, видео, каналы

Worker дополнительно вызывает `runConnectors`: Битрикс24, 1С, Kaspi (не чаще раза в 15 минут на подключение), входящие события Битрикс24/Telegram и очередь исходящих Telegram. Все подключения настраивает владелец на странице «Подключения»; реквизиты шифруются `INTEGRATION_ENCRYPTION_KEY`.

- Telegram: токен бота → «Проверить» → «Зарегистрировать вебхук» (нужен публичный HTTPS-адрес приложения) → «Разрешить исходящие». Клиент привязывается кодом `/start <код>` (выдаёт сотрудник, 7 дней). Таймаут при отправке = «результат неизвестен», повтор вручную после проверки в Telegram.
- Kaspi: токен из кабинета продавца, филиал и склад. Заказы читаются автоматически; перенос, подтверждение в Kaspi, выдача, отчёт о выплате и возврат — на странице «Продажи», панель «Заказы Kaspi». Смена статусов в Kaspi включается владельцем отдельно. Комиссия и выплата вводятся из отчёта Kaspi.
- Банк: на странице «Финансы» привязать IBAN к счёту и загрузить файл 1CClientBankExchange; каждая строка проводится, сопоставляется или пропускается человеком.
- Видео: обработка идёт отдельным процессом на устройстве в сети камеры, нужен ffmpeg в PATH (или `FFMPEG_PATH`). Владелец создаёт источник и получает токен устройства (показывается один раз). Запуск: `VIDEO_DEVICE_TOKEN=… npm run video:processor -- --server https://<приложение> --source <id> --file clip.mp4` (или `--rtsp` с `VIDEO_RTSP_URL`, `--webcam <устройство>`). Учётные данные камеры остаются на устройстве; кадры не отправляются. Оценка: `npm run eval:video`.
- Продвижение: PDF-материалы скачиваются со страницы «Продвижение» после согласования; рассылка — только Telegram и только клиентам с согласием. Генератор изображений, e-mail/SMS и рекламные кабинеты не подключены.

Проверки 15.10.2026: временный кластер PostgreSQL и серверы e2e остановлены после прогона.
