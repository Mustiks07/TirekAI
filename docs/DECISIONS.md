## ADR-003: PGlite только для локальной синтетической среды

Docker CLI установлен, Docker Engine не запущен. Чтобы не менять настройки системного Docker, для локальной работы используется PGlite с диском, а для внешней БД подготовлен pg driver. PGlite одноподключённый: положительный тест не доказывает PostgreSQL-конкуренцию, lock semantics при нескольких процессах или нагрузочные цели. Это явная альтернатива окружения, не смена целевой архитектуры. [Документация PGlite](https://pglite.dev/docs/).

## ADR-008: первый импорт — контакты клиентов

T009 реализована на конкретной сущности, как допускает план. UTF-8 CSV/TSV, фиксированные external_id/name/email/phone, явный выбор разделителя, до 256 КБ/1000 строк. Используется реальный [csv-parse](https://csv.js.org/parse/options/), а не split по запятой. Namespace внешнего ID — филиал организации. Совпадение содержимого открывает прежний пакет; исправленная версия пропускает уже добавленные записи, а отличающиеся поля того же ID не перезаписываются. XLSX/сопоставление колонок/другие сущности — последующие расширения. Это не реализация обращений REQ CRM 02.

## ADR-009: общий worker и явный локальный адаптер

Outbox и задания находятся в БД. Резервирование через [FOR UPDATE SKIP LOCKED](https://www.postgresql.org/docs/current/sql-select.html), lease-token, порции по 25, до трёх попыток, одинаковый transactional processor для pg и PGlite. PGlite не может совместно открываться процессами: локальный worker использует приватный loopback-мост к web, PostgreSQL-worker работает напрямую. Это ограниченный dev-адаптер, не доказательство производственной конкурентности. Испытаны rollback, смена lease и возобновление файловой БД тремя независимыми процессами. Дополнительно PostgreSQL 18.2: два независимых пула без дублей и rollback при завершении backend; нагрузка нескольких OS-workers остаётся открытой.

## ADR-010: числа и контракт новых API

[decimal.js](https://mikemcl.github.io/decimal.js/) со своей конфигурацией precision 40 и HALF_UP; вход только десятичными строками, итоговые минимальные денежные единицы bigint. Не округлять цену до умножения количества. Новые API клиентов/импорта проверяют ответы Zod и публикуют [JSON Schema](https://zod.dev/json-schema) из тех же определений. Это частичное выполнение T002: прежние ответы и полная спецификация OpenAPI ещё впереди.

## ADR-011: складской журнал и цена возврата

Для первого собственного склада — средневзвешенная стоимость по SKU/складу. Количества numeric(21,6), окончательные суммы numeric(38,0)/bigint/string, расчёт пропорций precision 80; последнее списание/возврат получает остаток округления. [PostgreSQL numeric](https://www.postgresql.org/docs/current/datatype-numeric.html) вместо floating-point. Преобразования единиц задаются явно на SKU и блокируются после первой команды. Услуги не допускают складских движений. Партии и задние даты не имитируются, остаются открытыми.

Уникальная команда с хешем и [блокировка строки баланса](https://www.postgresql.org/docs/current/explicit-locking.html) в общей транзакции обеспечивают контроль повторов и проверку доступного остатка. Возврат привязан к выдаче; перемещение хранит стоимость в пути до приёмки. PGlite-тесты не объявляются проверкой нескольких PostgreSQL-процессов.

## ADR-012: PWA без кеша бизнес-данных

По [Next.js PWA guide](https://nextjs.org/docs/app/guides/progressive-web-apps) добавлены manifest, PNG-иконки, browser install event и service worker. [Жизненный цикл service worker](https://developer.mozilla.org/en-US/docs/Web/API/Service_Worker_API/Using_Service_Workers) используется для явной активации обновления. Кеш только публичных offline-ресурсов; операции требуют сеть, фонового replay нет. Это позволяет не сохранять контакты, стоимость и сессии в общем кеше устройства. Проверены manifest, offline/reconnect и cache allowlist, но не нативная установка на реальном Android/iOS.

## ADR-013: отдельный кластер для PostgreSQL-тестов

Найден локально установленный PostgreSQL 18.2. Runner создаёт новый кластер с собственными SCRAM-паролем и loopback-портом; системная служба не используется. Запуск/остановка через [pg_ctl](https://www.postgresql.org/docs/18/app-pg-ctl.html); Windows-реализация использует [ограниченный токен](https://doxygen.postgresql.org/pg__ctl_8c_source.html). Launcher запускается без наследуемых pipes, чтобы живой сервер не задерживал ожидание завершения команды. Пароль не передаётся в командной строке и не печатается. Файлы остаются в игнорируемом каталоге для диагностики, сервер останавливается в finally. Два независимых пула проверяют SQL-конкуренцию; это не подменяет многопроцессную нагрузку и backup/restore.


## ADR-014: отдельные факты исполнения, оплаты и возврата

T014–T016 используют собственный журнал событий заказа и журнал денег. Выручка появляется при исполнении после скидок, оплата отдельно уменьшает задолженность. Возврат привязан к исполнению и уменьшает его выручку/стоимость; возврат денег — отдельное действие. Отмена оставляет историю и уже исполненные суммы. Весь набор изменений заказа/склада/аудита выполняется одной SQL-транзакцией; внутренние stock-команды не публикуют обходной параметр в API.

Услуга с неизвестной стоимостью хранит NULL. Отчёт не выдаёт прибыль/проценты за известные при наличии неизвестных затрат; операционный результат всегда помечен неполным до подтверждения полноты расходов. Текущий налоговый режим — явно цены без косвенных налогов, без встроенных ставок и официальной отчётности. Период отчёта пока весь накопленный журнал филиала.

Календарь строит базу по неоплаченным подтверждённым заказам и обязательствам. Сценарий откладывает поступления и изменяет плановые выплаты, не изменяя записи. Просрочки переносятся на сегодня, регулярные будущие расходы не придумываются. Полноценный прогноз всех потоков, сохранение сценариев, измеренный эффект и банковский импорт остаются следующими задачами.
