# Платформа управления МСБ с AI

Рабочий локальный срез: аккаунт, организация, филиалы, команда, аудит, импорт/реестр клиентов, каталог, склад, заказы с частичным исполнением, ручные оплаты/возвраты, денежные счета, обязательства и финансовая сводка на казахском и русском. Есть платёжный календарь и сценарный прогноз. «Басқару» — временное обозначение интерфейса. Полная CRM, финансовый импорт, AI, голос, камеры и внешние интеграции ещё в плане.

## Локальный запуск

Требуется Node.js 22.20+ и npm. На Windows команды работают в PowerShell.

```powershell
npm ci
npm run dev
```

Открыть `http://127.0.0.1:3000`. Создать собственный тестовый аккаунт и организацию. Общего пароля нет. Использовать только вымышленные имена, почту и отдельный пароль. Минимальная длина пароля: не менее 12 символов.

Сервер привязан к loopback. Данные сохраняются в `.data/local` через PGlite (PostgreSQL в WebAssembly). Первый запрос инициализирует базу и миграции. Одновременно каталог может открыть только один процесс. Docker для этого режима не требуется.

Остановить web и worker: **Ctrl+C в терминале запуска**. Supervisor запускает один обработчик импорта, печатает его PID и останавливает вместе с сервером. Камеры и AI не запускаются. Папку `.data` не удалять для остановки.

Для проверки производственной сборки в локальном режиме:

```powershell
npm run build
npm run preview
```

Не запускать `dev` и `preview` одновременно на одной базе. `npm run start` предназначен для отдельно настроенного окружения, без автоматического включения локальной базы.

## Что проверить вручную

1. Зарегистрироваться, создать организацию и выбрать направление.
2. В разделе «Организация» создать второй филиал.
3. В разделе «Команда» создать приглашение на конкретный тестовый email с ролью и филиалом.
4. Скопировать ссылку и открыть в отдельном профиле браузера; зарегистрироваться с указанным email и принять приглашение.
5. Убедиться, что сотрудник видит только разрешённые сведения. Исключить его из аккаунта собственника; следующая проверка сессии сотрудника потребует входа.
6. Переключить ҚАЗ/РУ, обновить страницу, проверить сохранение данных и языка.
7. Открыть «Клиенты», выбрать филиал, скачать образец. Загрузить CSV/TSV UTF-8 до 256 КБ / 1 000 строк; столбцы `external_id,name,email,phone`, требуется email или телефон `+` и 7–15 цифр.
8. Проверить ошибки/дубли и подтвердить корректные строки. Дождаться результата, повторить тот же файл — он открывает прежний результат. Исправленный файл пропускает совпадающие записи и показывает конфликты вместо перезаписи.
9. Изменить контакт в реестре. Источник файла/строка остаются; запись защищена от потери параллельного редактирования проверкой версии.
10. В «Каталог и склад» добавить склад и товар (например kg и `bag=5`), затем выполнить приёмку. Цена операции относится к выбранной единице; склад хранит базовое количество.
11. Создать резерв, открыть «Резервы» и выдать его целиком либо снять. Попытка выдать больше доступного отклоняется. «Журнал» позволяет вернуть часть конкретной выдачи по исходной себестоимости.
12. Создать второй склад. Отправить перемещение, выбрать склад назначения и принять во вкладке «Перемещения». Пока товар в пути, на назначении доступного остатка нет.
13. Выполнить инвентаризацию с основанием. Для излишка ввести стоимость за базовую единицу. При изменившемся остатке закрыть форму и открыть её снова, чтобы получить свежую версию.

Услуги хранятся в каталоге без товарного остатка. Варианты представлены отдельными SKU с текстом варианта. Режим партий, ячеек, сроков/серийных номеров и документы заказов пока не реализованы. Цены каталога не меняют стоимость уже проведённых движений.

## PWA и потеря сети

В `npm run preview` подключается service worker и манифест. Если браузер предлагает установку, появляется кнопка «Установить приложение»; используется штатное подтверждение браузера. При обновлении сначала сохранить формы и нажать «Обновить приложение». В dev регистрация отключена.

После первого открытия при потере сети показывается экран RU/KK с повторным подключением. Кеш содержит только публичный offline HTML и иконки. Бизнес-данные, сессии и API не кешируются, фоновой отправки офлайн-операций нет. Техническая проверка манифеста и восстановления пройдена в Edge; нативная установка на Android/iOS ещё не проверена.

Приглашения не отправляют почту. Токен передаётся во фрагменте URL и не попадает в URL HTTP-запроса. Ссылка действительна 48 часов, одноразовая; перевыпуск отзывает прежнюю. Приглашение нельзя принять другим аккаунтом.

```powershell
npm run lint

npm test
npm run build
npm run test:e2e
npm audit
```

Браузерные тесты используют установленный Edge на Windows, Chromium на Linux. Для Linux: `npx playwright install --with-deps chromium`. Они сами запускают сборку приложения на порту 3100 с отдельной синтетической базой. Перед ними требуется `npm run build`. Результаты и ограничения: `docs/TESTING.md`.

## Тестовые организации

При остановленном сервере можно выполнить `npm run db:seed`. Создаются две независимые торговые организации с двумя филиалами и разными собственниками. Уникальные случайные пароли записываются только в игнорируемый файл `.local/fixture-accounts.json`. Seed отказывается перезаписывать существующий файл или работать с внешней базой. Файл с паролями не публиковать. Ручная регистрация в интерфейсе работает без seed.

## PostgreSQL

Поддерживается отдельный драйвер `pg` через `DATABASE_URL`. Для запуска с существующей выделенной тестовой БД задать `DATABASE_URL` и `APP_ORIGIN`, затем выполнить `npm run db:migrate`. Драйвер, миграции и конкурентные команды проверены на отдельном локальном PostgreSQL 18.2. Нагрузка и восстановление из резервной копии ещё не проверены.

`npm run test:postgres` создаёт собственный временный кластер с синтетическими данными и выполняет 10 проверок через независимые SQL-пулы. Установленный PostgreSQL требуется; при нестандартном размещении задайте `PG_BIN` — каталог с `initdb`, `pg_ctl` и `postgres`. Команда не использует `DATABASE_URL` и существующие базы, выбирает случайный loopback-порт и останавливает свой кластер после тестов. Подробности: `docs/RUNBOOK.md`.

В PostgreSQL-окружении отдельный `npm run worker` обрабатывает задания напрямую через SQL; миграции запускаются заранее одним исполнителем. В локальном PGlite supervisor использует защищённый loopback-мост к единственному владельцу базы. Подробности и остановка: `docs/RUNBOOK.md`.

Саморегистрация доступна только при `LOCAL_PREVIEW=1`; в общем окружении необходим следующий этап identity: подтверждение почты, восстановление доступа, MFA и настройки эксплуатации. Живой запуск текущей версии не заявлен. Все создаваемые организации имеют `data_origin=synthetic`.

Переменные и безопасные заглушки приведены в `.env.example`. Для локальных команд значения задаёт `scripts/local.mjs`. Секреты не сохранять в репозитории.

## Заказ и деньги

1. Импортировать клиента в разделе «Клиенты», создать каталог и склад, провести приёмку товара.
2. В «Заказы» выбрать филиал, клиента и склад; задать до 30 уникальных позиций, количества, единицы, цены, скидки и срок оплаты. Цены задаются без косвенных налогов; налоговый расчёт не настроен.
3. Подтвердить заказ: все товары резервируются одной транзакцией. При нехватке хотя бы одной позиции весь заказ остаётся черновиком.
4. Исполнить часть строки. Выручка начисляется по исполненной части, склад списывается, остаток резерва сохраняется. Услуга не создаёт складского движения; неизвестная себестоимость не заменяется нулём.
5. В «Финансы» создать денежный счёт KZT и провести частичную оплату с привязкой к заказу. Выручка и полученные деньги показываются отдельно. Продавец проводит исполнение; денежные записи доступны owner/manager/finance.
6. Возврат оформить из конкретного исполнения заказа. Он корректирует выручку и склад, а возврат денег проводится отдельно. Отмена снимает только неисполненный резерв и не возвращает оплату автоматически.
7. Добавить ручное обязательство поставщику, затем оплатить его частично. Прочие поступления, операционные расходы и переводы между счетами не подменяют выручку от заказов.
8. Платёжный календарь показывает ожидаемые поступления/выплаты и источник каждой суммы. Изменить задержку поступлений и процент плановых выплат, сравнить сценарий с базой. Этот GET-расчёт не меняет реальные записи.

Сводка — за весь период выбранного филиала. Учитываются только введённые операции; полнота расходов не подтверждена. Это управленческий срез, не официальная налоговая отчётность. Обращения/предложения/PDF, импорт финансов, банковский адаптер, связи с закупочными заказами и расширенная периодная аналитика остаются открытыми.
